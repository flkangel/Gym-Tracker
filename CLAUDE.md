# CLAUDE.md

Guidance for Claude Code (and humans) working in this repo.

## What this is

Single-user personal gym tracker: mobile-first PWA for iPhone, later wrapped
with Capacitor. Replaces the spreadsheet `data/private/DOCUMENTO DE
SEGUIMIENTO.xlsx` and adds nutrition logging. Multi-user safe by design (RLS).
Roadmap and status: `README.md`. Decisions: `docs/adr/`.

## Stack

Vite 8 + React 19 + TypeScript 6 (strict) SPA · TanStack Router (file-based)
and Query · React Hook Form + Zod · Tailwind CSS 4 + shadcn/ui (Radix) ·
vite-plugin-pwa · Supabase hosted (Postgres, Auth via email OTP, Storage) ·
Dexie for offline-first (Phase 4) · Vitest + Testing Library · Playwright
(WebKit, iPhone 15) · Vercel (Git integration) · pnpm via Corepack · Node 24.

## Conventions

- Code, identifiers, tables, commits and docs in **English**; all UI copy in
  **rioplatense Spanish** (voseo: "registrá", "cargá", "tenés").
- Conventional Commits (commitlint enforces); small atomic commits; one PR per
  phase into `main` from `phase-N/<slug>`.
- Prettier formats, ESLint (type-checked strict) lints; no `any`, no
  non-null assertions without a comment.
- Touch targets >= 44 pt (`h-11`), dark theme by default, contrast AA, safe
  areas via `env(safe-area-inset-*)`.
- Server state through TanStack Query; forms with React Hook Form + Zod
  schemas that double as types.
- Platform-dependent APIs only through `src/platform/`.
- Tests: Vitest for pure logic and components (mandatory for the recovery
  score formula, volume calculations and import parsers); Playwright for
  critical flows.

## Database rules

- Schema changes only through migrations in `supabase/migrations/`
  (`pnpm db:new`). Never edit the hosted schema by hand.
- **Every new table: migration + RLS enabled + policies on
  `auth.uid() = user_id` + a test.** Synced tables also carry `id uuid`
  (client-generated UUID v7), `user_id`, `created_at`, `updated_at`,
  `deleted_at`, and an index on `(user_id, <date>)`.
- One hosted project serves dev **and** prod: run `pnpm db:push:dry` before
  `db:push`; take a backup before destructive migrations or imports.
- **Never** run `supabase db reset --linked`, `supabase db push --include-all`
  without review, or anything with the service-role key from the client.
- Regenerate types (`pnpm db:types`) after each migration.

## Hard rules

- Never commit personal data, `data/private/`, spreadsheets, photos or `.env*`
  (only `.env.example`). Never send personal data anywhere except the owner's
  Supabase project.
- Never put secrets behind a `VITE_` prefix; the client only uses the
  publishable key.
- Never invent formulas, reference values or "healthy" ranges (body-fat
  formula, MRV/MEV, macro targets): make them configurable and ask the owner.
- Never rewrite git history or force-push without explicit OK; ask before
  pushing or opening PRs.
- Don't bypass hooks (`--no-verify`). If gitleaks flags something, stop and
  report it.
- Adding an external origin (API, CDN) requires updating the CSP in
  `vercel.json`.
- Work phase by phase: list files before starting, stop at the end with a
  summary and how to test, wait for OK.
